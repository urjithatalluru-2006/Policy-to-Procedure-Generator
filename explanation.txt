# Policy-to-Procedure Generator

> **Transform complex organizational policies into clear, actionable, and traceable Standard Operating Procedures (SOPs).**

Policy-to-Procedure Generator is an enterprise-oriented document intelligence platform that converts lengthy and ambiguous organizational policy documents into **step-by-step procedures, execution checklists, and role-specific instructions** while preserving compliance requirements and providing source-clause traceability.

The platform uses **Google Gemini AI** to analyze policy documents, identify actionable requirements, and generate structured procedures grounded in the original policy text.

---

## ✨ Features

* 📄 **Multi-Format Document Ingestion**

  * PDF
  * DOCX
  * TXT

* 🤖 **AI-Powered Procedural Synthesis**

  * Converts complex policy language into actionable instructions
  * Uses Google Gemini for intelligent document analysis
  * Reduces passive and ambiguous language
  * Preserves important business and compliance constraints

* 🔎 **Clause-Level Citation Grounding**

  * Every generated action can be linked back to its source clause
  * Example: `[Sec 3.2]`
  * Improves auditability and compliance traceability

* 👥 **Role-Based Procedures**

  * General Staff
  * Managers
  * Technical Support
  * System Administrators

* 🌓 **Dual-Pane Document Viewer**

  * View original policy clauses alongside generated procedures
  * Easily compare source requirements with actionable instructions

* 📋 **Multiple Output Formats**

  * Step-by-Step SOP
  * Interactive Checklist
  * Structured Markdown

* 🔄 **Interactive Processing Pipeline**

  * Document Parsing
  * Semantic Chunking
  * AI Synthesis
  * Procedure Generation

* 📤 **Export Utilities**

  * Export procedures to PDF
  * Copy generated Markdown
  * Use interactive checklists

* 📚 **Procedure History**

  * Access previously processed policies
  * Maintain a convenient workspace for generated procedures

# 🔄 Processing Pipeline

The application processes policy documents through four major stages.

### 1. Document Ingestion

Uploaded policy documents are parsed to extract their raw content while preserving:

* Clause numbers
* Section headings
* Subsections
* Organizational hierarchy
* Relevant policy terminology

Supported formats:

```text
PDF
DOCX
TXT
```

---

### 2. Semantic Chunking

The extracted policy text is divided into meaningful semantic sections.

The system attempts to preserve relationships between:

* Sections
* Subsections
* Requirements
* Exceptions
* Roles
* Responsibilities
* Compliance constraints

This structured representation is then passed to the AI synthesis layer.

---

### 3. AI Procedural Synthesis

Google Gemini analyzes the structured policy content and transforms policy requirements into actionable procedures.

The synthesis process extracts:

```text
Prerequisites
      ↓
Responsible Role
      ↓
Required Action
      ↓
Expected Outcome
      ↓
Source Clause
```

The generated instructions are designed to use clear, imperative language rather than passive or ambiguous policy wording.

Example:

**Policy Language**

> Employees must ensure that access credentials are periodically reviewed in accordance with the organization's access control requirements.

**Generated Procedure**

```text
1. Review active user accounts.
2. Identify accounts that no longer require access.
3. Remove or disable unnecessary access.
4. Document the review.
5. [Sec 3.2]
```

---

### 4. Citation Grounding

Each generated procedure is associated with its originating policy clause.

Example:

```text
Step 1: Review all active accounts. [Sec 3.2]

Step 2: Identify accounts that no longer require access. [Sec 3.2]

Step 3: Disable unnecessary accounts. [Sec 3.3]
```

This provides a traceable relationship between:

```text
Policy Requirement
        ↓
Source Clause
        ↓
Generated Action
```

This is particularly useful for auditing, compliance reviews, and organizational governance.

# 🚀 Getting Started

## Prerequisites

Make sure the following are installed:

* Node.js `18.0.0` or higher
* npm or Yarn
* Google AI Studio API key

---

## 1. Clone the Repository

```bash
git clone https://github.com/urjithatalluru-2006/Policy-to-Procedure-Generator.git
```

Navigate into the project:

```bash
cd Policy-to-Procedure-Generator
```

---

## 2. Install Dependencies

Using npm:

```bash
npm install
```

Or using Yarn:

```bash
yarn install
```

---

## 3. Configure Environment Variables

Create a `.env` file in the project root:

```env
VITE_GEMINI_API_KEY=your_gemini_api_key_here
```

Replace:

```text
your_gemini_api_key_here
```

with your Google AI Studio API key.

### ⚠️ Security Note

Never commit your `.env` file or expose API keys in source control.

Make sure `.env` is included in `.gitignore`:

```gitignore
.env
.env.local
```

---

## 4. Start the Development Server

Run:

```bash
npm run dev
```

Vite will start the local development server.

Open:

```text
http://localhost:5173/
```

in your browser.

# 🔐 Security Considerations

Because this application processes potentially sensitive organizational policies, security is an important consideration.

Recommended practices include:

* Never commit API keys to Git
* Store production secrets in environment variables
* Enable HTTPS in production
* Restrict access to the EC2 instance
* Configure Firebase authentication domains correctly
* Use secure authentication flows
* Apply appropriate IAM and server permissions
* Avoid logging sensitive policy content unnecessarily
* Validate uploaded documents before processing

# 🤖 AI Processing Philosophy

The AI layer is designed to **transform policy language rather than invent policy requirements**.

The generated procedure should:

* Preserve explicit requirements
* Preserve important restrictions
* Preserve exceptions
* Preserve role responsibilities
* Reference the originating policy clause
* Avoid introducing unsupported requirements
* Convert passive language into actionable instructions
* Clearly distinguish required actions from contextual information

The original policy remains the authoritative source.

# ⚠️ Disclaimer

The Policy-to-Procedure Generator is an AI-assisted document transformation system.

Generated procedures should be **reviewed by an appropriate policy owner, compliance officer, manager, or subject-matter expert before being used as an authoritative operational procedure**.

AI-generated output may contain inaccuracies or interpretations that require human validation.
